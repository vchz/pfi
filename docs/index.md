# PFI Documentation

PFI (Probability Flow Inference) provides estimators to learn a score model and a probability-flow model from time-resolved cross-sectional data.

## Installation

```bash
git clone git@github.com:vchz/pfi.git
cd pfi
pip install -e .
```

Main dependencies include `numpy`, `torch`, `tqdm`, `POT`, `geomloss`, `torchcubicspline`, and `scanpy`.

## Quick Start (composite estimator)

### Data format and loading

All estimators expect a matrix `X` with shape `(n_samples_total, ndim + 1)`:

- columns `0..ndim-1`: state variables
- last column: time

If you already have snapshots by time, convert them with:

```python
from pfi.utils.data import X_from_snapshots

X = X_from_snapshots(snaps, times)
```

`pfi.utils.data.load_data` accepts either:

- a local `.h5ad` / `.h5ad.gz` path
- aliases `"natcomm"` or `"kaggle"`

For aliases, data is fetched from the package Zenodo repository (`https://doi.org/10.5281/zenodo.19237707`) and cached in `pfi.utils.data.PFI_DATA_FOLDER` (default: `~/pfi_data`).

`load_data` returns:

- `(samples, unique_times)` if `cell_type_key=None`
- `(samples, unique_times, ind_array, cell_types)` otherwise

### Using a composite estimator

The high-level entry point is `make_pfi_estimator`. It builds a score estimator and a flow estimator, then the `PFI.fit` routine fits score first and flow second.

```python
import torch
from pfi import make_pfi_estimator

device = "cuda" if torch.cuda.is_available() else "cpu"

est = make_pfi_estimator(device=device, seed=0)
est.fit(X)
```

You can configure `make_pfi_estimator` through these options:

- `score_model`: score model instance (default: `DSMScore(...)`)
- `flow_model`: flow model instance (default: `CLEFlow(...)`)
- `growth_model`: optional growth model instance (`None` by default)
- `s_solver`, `f_solver`: solver names for score and flow
- `s_solver_kwargs`, `f_solver_kwargs`: solver hyperparameters (including `lr`, `n_epochs`)
- `fit_on_score_samples`: if `True`, fit flow on samples generated by the score estimator
- `device`, `seed`, `verbose`: runtime configuration

Typical customized call:

```python
est = make_pfi_estimator(
    score_model=score_model,
    flow_model=flow_model,
    growth_model=growth_model,
    s_solver="dsm",
    f_solver="pfm",
    s_solver_kwargs={"L": 5, "adp_flag": 0, "lr": 5e-4, "n_epochs": 4000},
    f_solver_kwargs={"fac": 2, "nb": 1, "lr": 1e-3, "n_epochs": 2000},
    fit_on_score_samples=False,
    device=device,
    seed=0,
    verbose=True,
)
```

### Quick note on the solvers

Score solver currently available:

- `dsm`: denoising score matching.

Flow solvers currently available:

- `pfm`: unbalanced flow matching solver used in this package
- `upfi`: UPFI/PFI-style solver
- `external.deepruotv2`: external wrapper backend
- `future.ufm_uot`, `future.ufm_ot`: experimental solvers

References for `upfi` include `https://doi.org/10.48550/arXiv.2505.13197` and `https://doi.org/10.1073/pnas.2420621122`.

### Hyperparameter optimization

`hyperopt_pfi` is present in the API but is currently not implemented in this version.

## Low level usage

If you want full control, train score and flow separately.

```python
from pfi import make_score_estimator, make_flow_estimator
from pfi.flow.models import CLEFlow, AutonomousGrowth

score_reg = make_score_estimator(
    solver="dsm",
    solver_kwargs={"L": 5, "lr": 5e-4, "n_epochs": 4000},
    device=device,
)
score_reg.fit(X)

flow_reg = make_flow_estimator(
    flow_model=CLEFlow(score=score_reg.model_, lx=0.3),
    growth_model=AutonomousGrowth(),
    solver="pfm",
    solver_kwargs={"fac": 2, "nb": 1, "lr": 1e-3, "n_epochs": 2000},
    device=device,
)
flow_reg.fit(X)
```

You can also rely on default flow model creation and pass `score=score_reg.model_` to `make_flow_estimator`.

Main estimator methods:

- `ScoreModel.sample(X)`: generate samples at input times
- `ScoreModel.score(X)`: per-time energy distance between generated and observed samples
- `FlowModel.sample(X0, Dt, dt, stoch, pos)`: simulate trajectories from initial states
- `FlowModel.score(X, Y, ...)`: for each source time in `X`, push to the next strictly later time in `Y`, then compute energy distance

For full API details and runnable workflows:

- API reference: `docs/api/summary.md`
- Examples: `https://github.com/vchz/pfi/tree/main/examples`
